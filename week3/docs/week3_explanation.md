# Week 3：把多个有序 Run 存在一个文件里

## 1. 先想象一本有目录的书

有三个序列：`[-5,1,1,8,20]`、`[]`、`[0,3,9]`。每个序列内部有序，长度却不同；它们就是三个 Run。**各 Run 有序不意味着整个文件有序**：第一个 Run 的 20 后面可以是第三个 Run 的 0。

如果只把数字接在一起，读取者不知道哪里是第二个 Run，也无法区分空 Run。因此文件要像一本书：Header 说明这是什么书，Directory 说明每章从哪里开始、多长，Data 放正文。找第三章先查目录，不必先读完前两章。

外存访问比访问内存重。计算代码想“给我下一个数”，文件层却适合“一次给我一批数”。InputBuffer 和 OutputBuffer 正是两者之间的翻译层。它们只保存一个固定容量的块，而不是整份文件。

## 3. 先确定 Scan、Put、Search 是什么

| 操作 | 语义 | 边界 |
|---|---|---|
| `scan(run, first, count, B, visitor)` | 依次回调指定 Run 的 `[first,first+count)` | 下标从 0 开始；`first==长度,count==0` 合法；越界抛异常；空扫描不读数据 |
| `put(value)` | 给当前正在构造的 Run 追加一个数 | 必须先 begin；必须非递减；重复值合法；无序值在修改状态前被拒绝 |
| `search(run,key,B)` | 找到第一个等于 key 的 Run 内下标 | 返回 `optional<uint64_t>`；不存在返回 nullopt；Run ID 非法报错，不与“没找到”混淆 |

Put 的“追加”有两层含义。逻辑上，它扩展当前 Run 的末尾；物理上，满一块才写入文件，未满时值仍在内存中。`end_run()` 刷出尾块并写目录，之后该 Run 封存，只能新建下一个 Run。**本接口不支持对已封存 Run 追加，也不支持中间插入或覆盖。** 它不是数据库任意位置更新接口。

例如 `[1,4,9]` 后追加 10 保持有序；追加 3 会被拒绝。若要插入 3，应得到 `[1,3,4,9]`：需要后移 4、9；如果后面还有其他 Run，还必须搬移它们并修改目录偏移。更适合外存的方法是扫描原文件，把新值合并写入新文件，完成后再替换。本周只解释这种 O(N) 重写成本，不实现此额外操作，也不以覆盖数据伪装成插入。

Search 依赖 Run 有序。Writer 保证自己生成的 Run 有序；Reader 打开时只验证结构，不为每次打开扫描全部数据。读取未知来源文件时，可先调用 `validate_sorted`，代价是一次完整扫描。结构合法不等于数据无损，本格式没有校验码。

## 4. 文件格式与地址计算

所有数字按固定宽度的小端字节编码；禁止直接把 C++ struct 的内存写到文件，因为编译器填充、类型宽度和端序可能不同。Data 使用 32 位二进制补码。编码/解码在 `src/buffer.cpp` 的 `detail::encode/decode`；负数解码先转换到 int64，再转换到 Value，避免超范围无符号转有符号的实现相关行为。

| Header 字节偏移 | 字节数 | 字段 |
|---|---:|---|
| 0 | 8 | magic，ASCII `RUNF17` 后接 CR、LF |
| 8 | 4 | version = 1 |
| 12 | 4 | value_bytes = 4 |
| 16 | 8 | max_runs，预留槽数量 |
| 24 | 8 | run_count，已经封存的 Run 数 |
| 32 | 8 | directory_offset = 64 |
| 40 | 8 | data_start = 64 + 32 × max_runs |
| 48 | 8 | data_end，数据末端的下一字节，也等于文件长度 |
| 56 | 8 | 保留字段，必须为 0 |

每个目录项 32 字节：`id / count / offset / bytes`，各 8 字节；`bytes == count*4`。第 r 项位置为 `64+32*r`。Run 按目录顺序连续放置，无间隙，无块填充；空 Run 合法，其 offset 与后继 Run 可以相同。预留但未使用的槽初始化为零，Reader 不把它们当有效目录项。

演示预留 5 个槽：Data 从 `64+5*32=224` 开始。

| Run | count | offset | bytes | 下一位置 |
|---|---:|---:|---:|---:|
| 0 | 5 | 224 | 20 | 244 |
| 1 | 0 | 244 | 0 | 244 |
| 2 | 3 | 244 | 12 | 256 |

Run 0 的第 3 个下标，即值 8，在 `224+3*4=236`。注意：字节地址、记录下标、块号是三个不同的量。

工程上限制目录最多 1,048,576 槽，块最多 16,777,216 条记录；它们是防止不合理分配的限制，不是算法必需。`max_runs=0` 合法，只能生成一个无 Run 的 64 字节文件；B=0 始终非法。

## 5. 缓冲区怎样工作：逐步跟踪 B=3

### 顺序读取和缓存

读取 `[-5,1,1,8,20]`：

1. `next` 要下标 0，缓存为空，`at(0)` 读取前三个数，共 12 字节。
2. 下标 1、2 都命中当前块，不发出新 read。
3. 下标 3 不在块内，读取尾块 `[8,20]`，只有 8 字节，不能越过 Run 边界读到下一个 Run。
4. 下标 4 命中尾块；下标 5 是 EOF，`next` 返回 false，不改调用者的值，不额外读文件。

`at(i)` 用 `start=(i/B)*B` 定位块起点。这里块相对 **Run 起点** 对齐，不是硬盘扇区，也不是绝对文件偏移的 B 倍数。`valid_` 是实际载入数，尾块可能小于容量。随机访问 `at` 不推进顺序游标 `cursor_`；`seek` 只移动游标。

这既包含 Buffering（批量搬运），也包含 Caching（同块重复访问直接复用）。仅有一块意味着跨块来回访问可能反复读，不存在完整缓存池替换算法。

### 顺序输出与尾块

1. 连续 Put -5、1，`used_` 为 2，尚未 write。
2. Put 1 后满 3 个数，自动 `flush`，一次写 12 字节，`used_` 清零。
3. Put 8、20 后又有两个脏值。
4. `end_run` 调用 `flush` 写最后 8 字节，再写目录项。
5. 空 Run 只写目录，不写 Data；重复调用空 flush 不增加计数。

`used_>0` 就是这里的“有脏数据”。必须显式调用 `end_run` 与 `finish`，不能依赖析构报告写入错误。析构仅由标准流释放资源；未完成的文件保留无效头，应视为失败产物，不能继续读取或恢复。

### 二分 Search 的例子

对 Run 0 查找 1，区间 `[low,high)=[0,5)`：

1. mid=2，值为 1，说明第一个 1 可能更靠左，high=2。
2. mid=1，还是 1，high=1。
3. mid=0，值为 -5，小于 1，low=1。
4. low==high==1；再确认该位置的值等于 1，返回下标 1。

上述访问都在第一块里，所以只产生一次 12 字节 Data read。不要一碰到相等就返回，否则重复值的答案不稳定。循环就是 `lower_bound`：保留“第一个不小于 key 的位置”。如果结果等于 n 或该值大于 key，则不存在。

## 6. 逐个类、成员和函数对应实际代码

### `IOStats`、`RunEntry` 与字节辅助函数

`include/external/buffer.hpp` 的 `IOStats` 分开记录 Data 与 Metadata 的成功 read/write 次数和字节数，共 8 个计数器。`RunEntry` 对应 4 个目录字段，只有一条在内存中，不是整张目录数组。

`checked_capacity` 验证 B；`read_exact/write_exact` 检查流位置可表达范围、seek 和实际传输成功。短读直接抛异常；失败传输不计为成功 I/O。`meta_read/meta_write` 是文件实现内部包装，确保元数据不混入 Data 计数。

### `InputBuffer`（`buffer.hpp` / `buffer.cpp`）

- `in_ / stats_`：借用输入流和计数器；调用者必须让它们活得更久。
- `offset_ / count_`：当前 Run 的地址和记录数；禁止越 Run 读。
- `cursor_`：下一次 next 的下标。
- `block_start_ / valid_`：当前缓存覆盖的起始下标和实际记录数。
- `capacity_ / block_`：固定容量及编码字节数组，占 4B 字节。
- 构造函数：分配一块并验证地址范围；不立即读取 Data。
- `at`：越界检查 → 命中判断 → 必要时读块 → 解码；失败读取前清除 valid，避免把半读数据当有效缓存。
- `next`：EOF 判断 → at(cursor) → 成功后递增。
- `seek`：校验后修改游标，可以移动到 EOF。

### `OutputBuffer`

- `out_ / stats_`：借用输出流和计数器。
- `offset_`：下一批写入的字节地址。
- `capacity_ / used_ / block_`：容量、脏记录数及固定编码缓冲。
- `failed_`：写失败后禁止继续使用，避免重试产生越界或重复写。
- 构造函数：分配块；`put` 编码并在满块时 flush；`flush` 写 used 个值，成功后推进 offset 并清零 used。

OutputBuffer 是通用顺序写入部件，不负责有序性；顺序约束在 Writer 层。其 flush 是将应用缓冲写入 C++ 流，**不等于操作系统强制持久化**。

### `RunFileWriter`（`run_file.hpp` / `run_file.cpp`）

- `file_`：拥有输出文件流；需要回写文件头及目录，因此为二进制读写流。
- `stats_ / capacity_`：计数器引用及每 Run 的缓冲容量。
- `max_runs_ / runs_`：目录容量与已封存数量。
- `data_start_ / end_`：数据起点、已封存数据末端。
- `count_ / last_`：当前 Run 已接受数量与末值；optional 区分空 Run，不能用某个整数作空哨兵。
- `output_`：当前 Run 的输出缓冲；空指针表示没有活动 Run。
- `finished_ / failed_`：防止完成后写入及 I/O 失败后继续操作。
- 构造函数：拒绝已有路径，固定 4096 字节零块初始化头和目录，避免按目录总大小分配内存。
- `ensure_open`：共同状态检查。
- `begin_run`：检查没有活动 Run 和目录未满，创建缓冲，重置计数及末值。
- `put`：先检查状态、有序性及地址上限，再交给缓冲，成功后更新 count/last。
- `end_run`：先刷数据，再写目录项，再推进 end/runs 并销毁活动缓冲。
- `finish`：禁止仍有活动 Run；flush 数据流，最后写有效 Header、flush 并 close，所有失败可抛出给调用者。

这样未 finish 的常规中断产物没有有效 magic，不会被误读为完整文件。但这不是事务系统：标准库没有跨进程独占创建或断电原子提交保证；同一路径只允许单个串行 Writer，禁止其他进程并发修改。实际 I/O 失败后保留失败产物供排查，不自动覆盖或重试。

### `RunFileReader`

- `file_` 拥有输入流，`stats_` 借用计数器；`max_runs_ / runs_ / data_start_ / end_` 保存 Header 信息。
- 构造函数：验证头、文件长度，再逐条检查目录连续性；不读取整份 Data。
- 四个 getter：返回头信息。
- `directory`：按槽定位并读取单条目录，检查 ID、地址及 count/bytes 一致性。
- `input`：为指定 Run 返回独立 InputBuffer；Reader 和 stats 必须比它活得久。
- `scan/search/validate_sorted/display`：分别实现区间遍历、首匹配二分、数据有序性扫描、带目录信息的显示。

多个 InputBuffer 可串行交替使用同一 Reader，因为每次缓存未命中都会重新 seek；缓存是各对象自己的。**这些对象没有线程同步，不允许同时跨线程访问。** 多线程只属于后续周任务。

### 演示与测试辅助

`src/main.cpp::main` 给出完整生成和读取调用链，捕获异常并返回非零退出码。固定输入是用于讲解的小样本，没有将外存数据整体排序。

`tests/week3_tests.cpp` 的 `check` 使用异常而不是 assert，因此 Release 下仍执行检查；`rejects` 检查非法操作会抛异常；`passed` 输出分组结果。`Sandbox` 只拥有并清理自己新建的临时目录；`patch` 使用独立编码给复制的样本注入损坏。随机测试的小向量是独立 oracle，不属于外存算法的工作内存。

## 7. 调用链与数据流

```text
生成：main → Writer.begin_run → Writer.put → OutputBuffer.put
                                           └→ 满块 flush → write_exact → 文件 Data
      Writer.end_run → 尾块 flush → meta_write → 文件 Directory
      Writer.finish → 流 flush → meta_write → 文件 Header → close

扫描：Reader.scan → directory → InputBuffer.seek → next → at
                                                        ├→ 缓存命中：解码
                                                        └→ 未命中：read_exact → 解码
                                                    → visitor(value)

查询：Reader.search → directory → lower_bound 循环 → InputBuffer.at(mid)
                                         → 最后相等检查 → optional 下标
```

数据只从文件进入一块缓冲，再逐个交给使用者；Scan 不收集结果数组。调用者若在 visitor 中无限 push_back，会自行引入 O(N) 内存，这不是 Scan 所必需的行为。百万记录测试只计算计数、顺序断言和校验和。

## 8. 时间、空间和 I/O 成本

设 B 为记录容量，n 为某 Run 长度，R 为有效 Run 数，M 为预留目录槽数。下表把应用层 read/write 视为一次传输；操作系统页缓存、C++ 流内部缓冲与硬盘实际读写不在本计数中，不能把统计称为物理磁盘次数。

| 操作 | CPU/记录处理时间 | 额外工作内存 | Data I/O |
|---|---|---|---|
| 创建空文件结构 | O(M) 写入字节 | 固定 4096 字节 | 0；元数据初始化 ceil((64+32M)/4096) 次 |
| 写一个 n 元素 Run | O(n)，另有块分配初始化 O(B) | O(B)，编码数组 4B 字节 | ceil(n/B) 次写，4n 字节 |
| 打开 Reader | O(R) | O(1) 目录工作内存 | 0；读 Header 1 次、目录 R 次 |
| 完整 Scan / 有序性验证 | O(n+B) 含缓冲初始化 | O(B) | ceil(n/B) 次读，4n 字节 |
| 区间 Scan k 个元素 | O(k+B) | O(B) | k=0 时 0；否则 floor((first+k-1)/B)-floor(first/B)+1 次 |
| Search | O(log(n+1)+B) 含缓冲初始化 | O(B) | 最坏 O(log(n+1)) 次块读取；同块命中可减少 |
| display | O(N+RB) 加文本输出 | O(B) | 各 Run 的 ceil(n/B) 之和 |

块向量构造会初始化 4B 字节，所以表中保留 +B；通常固定 B 时将扫描记为 O(n)、查询记为 O(log n)。目录方法每次额外一次 32 字节读取；display 每 Run 为显示和 scan 各读一次目录。写每个目录项一次，finish 再写 64 字节 Header。初始化会写保留区，因此总元数据字节数可能大于文件元数据区大小。

例：B=3，长度为 5、0、3，则生成和完整扫描 Data 各需 `2+0+1=3` 次。B=127，n=1,000,003，则各需 7,875 次，传输 4,000,012 字节。小 B 的作用是让块边界更容易观察，不表示实际工程推荐这么小的块。

Search 不是 B 树搜索；它只是借助单块缓存的二分搜索，不能声称达到 O(log_B n)。缓冲只有 O(B)，不会随文件记录总数 N 增长；文件占用仍为 O(M+N)。

## 9. 最容易写错的地方

1. 空 Run 必须有目录项，不能因为没有 Data 就消失；空 Run 的共享偏移是合法的。
2. 尾块不能按完整容量读取，否则会跨 Run，甚至将 EOF 当成普通数据。
3. 判断扫描范围用 `count > length-first`，先检查 first，避免 `first+count` 溢出。
4. 文件头、目录、数据的偏移单位都是字节；元素下标转换要乘 4。
5. 重复值使用非递减规则；Search 要返回第一个重复值。
6. 未满缓冲不能丢弃；end_run 先写尾块再写目录，finish 最后写有效头。
7. 文件长度、count*4、streamoff 地址必须校验；先做除法界限验证，避免乘法先溢出。
8. 不能只让 Writer 和 Reader 相互验证：两者若犯相同编码错误，也可能通过往返测试。因此额外检查原始字节。
9. 输出失败后停止使用相关对象；析构不能代替显式 finish 的错误检查。
10. 不得把计数器的 read 次数解释为真正硬盘寻道次数；不同缓存层影响物理访问。
